# 0016 — Phase 4 implementation choices (portal, free tier)

- **Date:** 2026-10-11
- **Status:** Proposed (part of the Phase 4 approval)

## Decisions

1. **One tier check, impossible to bypass by construction.** `web/lib/entitlements.ts` decides. The only function
   that reads the database (`web/lib/db.ts`) accepts only the grant that check returns, reads only that model's own
   published output tables, only its current version, and never past a free preview's date. Unit tests check the
   structure (nothing else imports the database driver; every data function goes through the check).
2. **The site reads the database as `web_reader`**, a role that can only select from the `models` schema (migration
   0006). Row-level security is on for every table, so any other non-owner role, such as the browser roles a
   Supabase project creates, reads nothing even if a schema were exposed by mistake.
3. **Every page renders per request on the server**, and API responses are `private, no-store`, so no shared cache
   can hand one tier's page to another. The build test checks that no data page is built ahead of time.
4. **Accounts are stubbed until the Supabase project exists:** every visitor is anonymous and on the free tier.
   `web/lib/viewer.ts` is the one place that changes when Supabase Auth is added. Tests act as other tiers with a
   header that works only when `ALLOW_TEST_TIERS=1` and the app is not running as production.
5. **Proposed tiers** (`config/entitlements.yaml`, the owner decides): free: the stock market summary, every
   share's metrics, the bond list and quotes, the yield curve, bond trading activity; Plus: residual z-scores
   (with a free preview delayed 5 days) and the trades-against-quotes gap; Pro: carry, rolldown and duration.
6. **Computed but not shown to anyone:** the pair-spread reversion statistics. Next to a pair they would read as a
   performance claim (audit §8), so they wait for a legal view.
7. **English only at launch, with no language prefix in addresses.** All text is in `web/messages/en.json` with
   typed keys (a missing key fails the build); Sinhala and Tamil are added by translating `si.json` and `ta.json`
   and listing them in `web/i18n/request.ts`.
8. **Plain Postgres access (`pg`) rather than the Supabase JavaScript client**: the site only reads pre-computed
   tables on the server, which needs nothing more.
9. **The model registry is copied into the web app** (`web/lib/generated/registry.json`, regenerated by
   `python -m data_platform.models.registry export-web`; CI fails if it is stale), together with the method pages,
   disclaimers and trading calendars, so the web app never reads files outside `web/` on Vercel.
10. **npm runs with `legacy-peer-deps`** (`web/.npmrc`): npm's resolver crashes on this dependency tree; every peer
    the app needs is listed explicitly instead.

## Not built yet (and why)

- Sign-up, log-in and payments: they need the Supabase project and the payment provider (owner accounts).
- Sinhala and Tamil text: needs translators; the structure is ready.
- Self-hosted Noto fonts for Sinhala and Tamil script: added with the translations.
- Deployment: needs the Vercel account. The build and the leak suite run in CI on every push meanwhile.
